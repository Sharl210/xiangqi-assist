# 象棋辅助 1.3 发布说明

## 版本信息

- 应用版本：`1.3`
- 版本代码：`4`
- 包名：`com.xiangqi.assist`
- 正式发布标签：`v1.3`
- 发布变体：通用 ARMv8 与 ARMv8 dotprod

1.3 基于已发布的 1.2，加入可在辅助页选择并记忆的 YOLO 三档模型。正式发行资产由推送 `v1.3` 标签触发的 GitHub Actions 工作流使用仓库加密密钥构建、签名并上传。

## YOLO 模型档位

- **大型**：真实双模型集成工件，逐检测锚点在 Medium 与 universal/旋转鲁棒模型之间择优，保持 `[1,640,640,3] → [1,25200,20]` 输出契约；目标是增强复杂皮肤、旋转和装饰差异下的鲁棒性。
- **中型**：现有单模型平衡档。
- **Lite**：资源与兼容性优先档。
- 新用户默认大型，历史选择继续保留。
- 兼容性探测只检查资产读取、Interpreter 创建、张量分配、输入输出形状/类型和一次受控推理。
- 自动回退顺序：大型 → 中型 → Lite。
- 当前负载、温度、功耗和速度只作为提示，不会因为设备当前较忙而强制降档。
- 大型模型工件来源、生成脚本和哈希记录见 `docs/YOLO模型档位评估.md` 与 `tools/build_large_ensemble.py`。

## UI 与运行行为

- 辅助页新增“识别模型”选择项，切换后后台检查兼容性。
- 兼容性失败时弹窗说明失败阶段和原因，并把设置同步到实际使用档位。
- 一键准备、悬浮窗开始/继续使用同一模型兼容性门。
- 模型切换先关闭旧推理对象，等待在途推理结束，再加载新档位。
- 帮助页面同步解释三档模型的能力、速度、功耗和回退规则。

## 验证边界

- 大型模型在构建主机上已通过 TFLite 输入输出契约、有限值和受控推理检查。
- 当前主机测得大型集成档推理耗时约为单个中型模型的两倍量级；该数据不是 Android 真机性能承诺。
- 全量 JVM 测试仍有 6 项 `OverlayChessViewRenderTest` 在 Linux/aarch64 图形环境失败，未计入通过；其余测试结果按工作区构建记录如实保留。
- 双变体 Release 和 `lintVital` 需要在当前最终源码上重新核验后，才以工作流正式资产为准。
- 真机上的复杂皮肤召回、设备兼容性、内存、功耗、温升和长时间运行仍需设备验收。
