# 移动端 V5 模型评估与样本优化

**适用范围**：当前工作版本；历史发行说明保留原样。路线限制为使用现成权重与本地转换，禁止从零训练。

## 当前产品结论

- 仅保留原始V5 Medium作为默认主模型，以及原始V5 Lite作为最终兼容回退。
- 仅在Medium运行时兼容性检查失败时转到Lite；低分本身不触发运行时自动降档。
- 用户切换设置只保存偏好，不创建悬浮窗、不启动识别、不热切换当前会话。
- 两个模型都使用同一V5输出解码、棋盘映射和安全门；复合High与YOLO26-S不再进入当前产品选项或APK资产。

## 实验样本的已有基线

在10张用户图片上，旧评测记录的样本安全门基线为：Medium 78.1/100、7/10通过；Lite 67.2/100、4/10通过。单线程热身后主机推理中位数约130ms和148ms。该分数不是准确率、召回率、F1或mAP；因没有逐格人工真值，也不能证明通过安全门的棋面每一枚棋子都正确。

现有逐张失败模式：

- Medium：10张中有3张未形成有效棋盘定位；前两张检测到两枚黑将且无法直接用于安全棋面；另外若干图通过原安全门。此项需要按Android实际映射链复现，当前不能把单独Python评测输出等同于设备结果。
- Lite：首批截图多张出现同格异类冲突；另有1张没有可靠棋盘框。双王本身在样本中均检出，但冲突帧仍必须拒绝。
- 当前运行日志来自当时的YOLO26-S版本，不可作为新V5版本的实机证明。

## 新增的棋盘框缺失复核路线

在整帧推理没有检测到棋盘类别、但棋子中心已足以形成可靠包围盒格网时，增加一次基于该格网的放大ROI复核。此操作不是直接接受当前棋面：二次结果仍必须有双王、无同格冲突、符合棋面结构，并通过既有合法性门，才可替换整帧结果。格网不足、过稀或几何异常时不触发复核。

该路径重点针对高分棋子都检出、但board类别漏检导致棋面定位失败的情况；它不会推断或回填棋子类别。通过新增的纯策略测试验证裁剪边界与锚点来源后，再用固定10张图片重跑V5 Medium/Lite对照。

## 后续实验纪律

1. 固定用户图片、捕获尺寸缩放、RGB顺序、letterbox、TFLite线程数和同一V5后处理版本。
2. 逐项记录棋盘定位来源、双王数量、映射格、同格冲突、合法性结果、主机耗时与模型哈希。
3. 参数改变须同时复测正例、冲突例、缺王/缺棋负例和所有当前图片；不得以“本批能过”为由关闭安全门。
4. 先用人工逐格标注核验类别、颜色、格点、板框；没有真值时只报告安全门通过率，不称逐格无误。
5. 主机耗时不代表Android真机延迟、功耗或温升；新APK须用增量版本发布，不覆盖v1.3.3。
