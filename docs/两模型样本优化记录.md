# 两模型收敛后的 V5 样本识别优化记录

**项目**：XQDK 象棋辅助
**适用代码状态**：V5 Medium + V5 Lite 双模型开发中；尚未构建或发布新 APK。
**样本来源**：`/workspace/测试log/` 下10张现有图片与 `最新1.3.3版本log/1.log`。

## 当前实验结论

- 用户可选模型与APK模型资产已在工作树中收敛到原始 V5 Medium 和 V5 Lite。
- 新增了仅在完整手机截图没有棋盘框、棋子中心可形成足够可靠的棋子包围盒格网、且当前映射不安全时触发的单次ROI放大复核。输出只有通过双王、无冲突与棋面合法性门才可替换原输出。
- Lite 同格冲突时新增一次独立置信阈值复核：棋子置信阈值提高到0.55、棋盘框阈值单独保持0.20；只允许无冲突、双王恰各一枚、合法且映射棋子数不低于基线的复核结果替换。复核失败继续拒绝，不把低分冲突棋面强行交付。
- 旧的1.3.3安全门评分作为历史基线保留：V5 Medium 78.1/100、7/10；Lite 67.2/100、4/10。该评测对所有样本都要求模型直接检出board类别，未把运行时支持的可靠 `PIECE_BBOX` 棋盘格锚点计入board有效，因此它不是本轮两模型优化后的最终分数，也不作为最终正确率结论。

## 预处理复核

完整手机截图为1440×3136，另有一张518×520的缩略错误结果图。录屏服务将长边缩放到1440后再送入640×640模型输入；因此评测脚本新增了“原图→录屏尺寸→letterbox”两阶段缩放复现。结果表明：Medium首批完整截图的模型board类别分数很低（约0.25和0.28），高置信棋子框仍形成可拟合的包围盒格网；这更像board类漏检/整屏小目标分辨率问题，而不能简单归因于棋子模型完全没识别到。

## 重要限制与下一步验证

- 样本缩略图没有逐格标注真值；必须人工标注棋盘交点、颜色、棋子种类与实际空格后，才能把“通过安全门”升级为“样本识别无误”。
- 这批图中出现双将/同格冲突意味着模型输出不可直接接受；低置信复核只可排除达到高阈值的低分候选，并且必须通过完整合法棋面校验，不能按置信度差直接覆盖原结果。
- 运行时ROI代码和Lite冲突复核已进入工作树，但本环境Android资源处理受AAPT2二进制架构阻塞，尚未完成JUnit执行、完整APK构建或真机复测。
- 下一个验证动作：用用户原始10张图在Android端的实际帧缩放、TFLite输入与正式后处理复放；逐图写出原始检测、格网来源、复核前后差异、双王/冲突/合法性结论，再用逐格人工真值确认是否识别无误。
- 本轮当前分数仍显示为历史基线，不宣称优化后满分；Lite阈值候选0.55/board 0.20在独立主机扫描中提高了安全门候选通过数，但尚未作为Android结果验收，不得直接改写成已验证新分数。
