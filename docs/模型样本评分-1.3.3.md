# 1.3.3模型样本安全门评分

**项目**：XQDK 象棋辅助
**版本**：1.3.3（versionCode 7）
**评测目的**：用用户提供的真实测试截图和当前应用同源后处理链比较四档模型；档位排序依据实际样本表现，不依据模型文件大小。
**评分性质**：这是“样本安全门评分”，不是有人工逐格真值时的准确率、召回率、F1或mAP。

## 样本与证据

本次共使用10张截图：

- `/workspace/测试log/最新1.3.3版本log/`中的6张1.3.3测试截图；
- `/workspace/测试log/最新log，异常卡死和识别错误/`中的2张异常截图；
- `/workspace/测试log/识别出错.png`；
- `/workspace/测试log/错误的识别结果。.png`。

最新1.3.3日志`/workspace/测试log/最新1.3.3版本log/1.log`包含：

- `VISION_RAW`：34次；
- `VISION_RESULT`：33次；
- `VISION_REJECT`：34次；
- `红帅数量异常:0`：33次；
- `MEDIUM`推理耗时：中位数约180ms，范围150–369ms。

这说明当前目标设备和目标皮肤下，Medium（YOLO26-S）仍然会重复提交缺少红帅的异常棋面，安全门正确拒绝了这些结果；不能因为模型名称较新或文件较大就把它排在更高档。

## 统一评测方法

四个模型均使用相同的：

- 640×640输入；
- RGB、letterbox预处理；
- 单线程TFLite主机推理，先完成热身；
- 当前应用对应的YOLOv5/YOLO26独立解码器；
- 类别感知NMS、棋盘几何过滤、棋盘格映射和同格异类冲突检查。

总分为100分，计算方式如下：

| 指标 | 权重 | 含义 |
| --- | ---: | --- |
| 棋盘框唯一有效 | 20 | 10张样本中恰有一个有效棋盘框的比例 |
| 双王同时识别 | 15 | 红帅和黑将同时出现的比例 |
| 无同格异类冲突 | 20 | 没有两个不同类别落在同一格的比例 |
| 严格安全门通过 | 30 | 同时满足棋盘框、双王、无冲突且有映射棋面的比例 |
| 有效棋子格覆盖 | 10 | 有效棋盘样本的中位映射格数相对32格的覆盖率 |
| 相对热身延迟 | 5 | 以本批最快模型为基准的相对主机延迟分 |

严格安全门仍然优先于置信度和检测数量：有同格冲突、缺帅/将、没有棋盘框或不能形成可映射棋面时，不计为可靠识别。

## 默认档与回退顺序

- 新安装默认选择当前评分最高的`Low`。
- 选择器按当前评分从高到低显示分数，但保留`Lite / Low / Medium / High`稳定名称。
- 兼容性探测只在用户选择档位及其评分更低的后续档位中回退：
  - `Low → High → Lite → Medium`；
  - `High → Lite → Medium`；
  - `Lite → Medium`；
  - `Medium`无更低评分档位。
- 负载、温度、功耗和速度不会单独触发兼容性回退；本报告中的延迟只参与样本评分，不替代设备兼容性判断。

## 限制与后续验证

- 当前截图没有完整人工逐格真值，因此评分不能证明任何模型的全面准确率；尤其不能据此声称Low或High在所有皮肤上都优于Medium。
- 1.3.3日志主要记录Medium运行结果，无法替代四个模型在同一台真机上的实时切换对照。
- 目标设备仍需补测冷启动、连续识别、P50/P95/P99、内存、功耗、温升、长时间稳定性和真实落子安全。
- Medium仍需单独修复或取得更好的固定样本证据；在双王、非法棋面和同格冲突安全门未闭合前，不得重新提升为默认档。
- 下一次新增真实样本后，应使用相同公式追加评测，并在评分发生变化时同步更新代码中的档位分数、帮助文档和默认选择。
