### 大型模型当前状态

Large 已接入真实双模型集成工件 `app/src/main/assets/yolov5l_xq_fp32.tflite`，输入输出契约与现有后处理一致；工件大小约54.26 MiB，SHA-256为`64c8746d458247fec62ea0347dd8a2587613b87269bad9cb0a052dfa310d65e5`。构建脚本为`tools/build_large_ensemble.py`，来源、生成方式和限制见`docs/YOLO模型档位评估.md`。它不是将Medium改名，而是Medium与universal模型逐检测锚点择优的真实集成档；识别质量和Android设备性能仍需真机验证。


完成 R1–R15，并在1.3中加入三档YOLO模型选择、兼容性探测与回退，在不损害原有识别校验、合法着法判断、落子后回执和恢复流程的前提下，提交可构建、测试、归档并发布的1.3版本。完成依据是当前源码的实际测试、APK元数据与内容检查、签名和哈希；历史构建和代码声明不算当前版本的证据。

本轮1.3最终验证需记录模型集成后的测试数量与失败项；双变体clean Release、两项`lintVital`、远程提交和正式Release以当前最终源码及公开回读结果为准。

本机没有连接真机。框选拖动、通知栏、系统共享指示、不同ROM上的Surface暂停/恢复、无障碍关闭核验、变招跨回合预存和真实棋盘点击轨迹均未完成设备验收；Large集成档的复杂皮肤召回、设备兼容性、内存、速度、功耗和温升也仍需真机验收。

## 已确定的设计边界

- 工作树从干净v1.1提交`cc67b6e`开始；早期未完成实验保留在`stash@{0}`和`/workspace/XQDK-wip-backup-20260922/`，不覆盖回现工作树。
- 一键准备只完成权限与屏幕会话准备，完成后保持暂停，不取帧、不识别、不计算；悬浮窗内的“开始”才启动工作。准备后控制页主按钮为红色“一键关闭”，运行和暂停时均不回退成“一键准备”。
- 暂停停止向应用输出帧、断开Surface并关闭`ImageReader`，保持无障碍前台监听，尽量保留投影授权与同一`VirtualDisplay`。重接失败或系统结束投影时才重新授权。
- 一键关闭释放投影与悬浮窗、撤销通知，并只关闭本应用无障碍服务。系统尚未确认服务停用时保持待关闭状态、阻止重新准备并提示设置操作。
- R14修订R9：不同棋子的预选起点选中点按间隔每次随机750–1250ms（含端点），首个预选不等待；正式落子起点到终点间隔继续使用既有220ms基准的30%–100%逐手随机策略。
- R15变招：不同阶段均可提前存储下一次我方实际落子的非默认候选意图；存量期间按钮文字为绿色，再次点击可取消并立即恢复白色；实际非默认落子核对完成后也恢复白色并清除存量。
- R3的预选快照可复用当时棋面及已算坐标，跳过落子前重复识图，但落子后仍核对新画面。只有匹配棋面/分析、预选手势已完成且无障碍实例未变时，才只点终点；其它情况走完整起点到终点手势。
- 应用版本号由`app/build.gradle.kts`统一维护为1.3/code 4。发布附件名、CI元数据核验、正式Release标签和发布说明均对应`v1.3`；1.2及更早历史工件与记录保持不变。

## 后续任务：YOLO模型档位选择、兼容性回退与性能评估

**状态**：Large真实集成工件、三档模型选择、持久化、兼容性探测、自动回退、辅助页同步、评估文档和帮助说明已接入；Large不是独立训练的YOLOv5-L，而是Medium+universal逐锚点择优集成，来源和限制已记录。当前最终测试、双变体构建、远程提交和Release发布需继续闭合；真机识别质量、设备兼容性、内存、速度、功耗和温升仍待验收。详细原话见 `plans/xqdk-20260924-log-investigation-timing-plan-01/request-addendum-01.md`。

### 任务目标

- 在悬浮窗辅助页加入 YOLO 模型选择，提供 Large、Medium、Lite 三档；新用户默认 Large，已有用户的选择持久化。
- 当前 Medium 资产为 `app/src/main/assets/yolov5m_xq_fp32.tflite`（约28.67 MB），Lite 资产为 `app/src/main/assets/yolov5n_xq_fp16.tflite`（约3.82 MB）；Large 资产为已接入的双模型集成文件 `app/src/main/assets/yolov5l_xq_fp32.tflite`（约54.26 MiB），不能把它描述为独立训练YOLOv5-L权重。
- 手动选择和一键准备/开始都执行同一兼容性探测。失败时按 Large→Medium→Lite 降级，并把最终档位、状态提示和设置界面同步为实际档位；三档均不可用时明确提示并不进入可识别运行态。
- 只按 Interpreter 创建、张量分配、输入输出形状、必要算子和受控探测执行判断兼容性；CPU负载、温度、功耗和速度只做提示，不触发自动回退。
- 新增 `docs/YOLO模型档位评估.md`，比较 Large/Medium/Lite 的识别质量、模型大小、速度、内存、功耗和温升；区分实测、规格推断与真机待测。同步 `docs/assist-helper.md`、`docs/help.html` 和 `app/src/main/assets/help.html`。

### 原子验收

1. 模型注册表、持久化字段、默认值和旧设置迁移测试通过。
2. 手动选择、兼容失败原因、自动降级、最终设置回写和 UI 同步测试通过。
3. 一键准备与悬浮窗开始/继续使用同一检查链；模型切换安全释放旧 Interpreter，不残留旧档位状态。
4. Large 工件来源、许可证、SHA-256、输入输出形状和类别契约已复读；大型集成的Medium+universal来源与构建脚本已记录，独立训练YOLOv5-L不作虚构声明。
5. 评估文档与三份帮助内容对三档模型的差异、提示和回退规则一致；未连接真机时不写虚构功耗、温度或准确率。
6. 相关定向测试、全量 JVM 测试、双变体构建和 `lintVital` 完成后，才进入设备兼容性、真实速度和功耗验收。
